# Database

PostgreSQL 16 with pgvector. Alembic owns the schema; extensions are created
once by `infrastructure/docker/postgres/init/00-extensions.sql` because they
need superuser rights.

## Conventions

- UUID primary keys, generated by the application (`UUIDPrimaryKeyMixin`).
- `created_at` and `updated_at` on every table, `timestamptz`, always UTC.
- Foreign keys are enforced in the database, not only in the ORM.
- Constraints belong in the database: uniqueness, check constraints, not-null.
- `imo_number` is unique across vessels.
- Every tenant-owned table carries `company_id`, and every repository query
  filters on it.
- No `SELECT *` in application code - columns are named explicitly so a schema
  change cannot silently widen a payload.

## Migrations

    alembic upgrade head                      apply
    alembic downgrade -1                      roll back one
    alembic revision --autogenerate -m "..."  generate from models

Run these from `apps/api`. The scripts live in `apps/api/app/migrations`, inside
the package, so they are deployed with the code rather than as a separate
directory that a checkout or image build can miss.

The API container runs `alembic upgrade head` on start; the worker does not
(`RUN_MIGRATIONS=0`), so two processes never race for the same lock.

## Current state

One revision, `0001_baseline`, which creates no tables. It exists so every
later migration has a common ancestor. Domain tables arrive in Phases 1 and 2
in the order set out in `data-model.md`.
